STG17 — HOW TO ADD A PRESENTATION OR A NOTEBOOK
================================================

One rule for both. Nothing is generated: you supply every file.

Find the placeholder, rename your file to match it minus "-inactif", drop it in
the matching docs/downloads/DayN/ folder, rebuild. Nothing else to edit.


1. THE TWO FOLDERS
------------------

    maintainer/placeholders/Day1..Day5/    the names, never published
    docs/downloads/Day1..Day5/             where you put the real file

The first tells you what to call your file. The second receives it. Only the
second is published with the site.

Placeholders are sorted by session start time, so each folder reads in the order
of the day.


2. ACTIVATING A FILE
--------------------

A placeholder carries "-inactif" before the extension. It means: nothing supplied
yet, and the site shows nothing for it.

    1430_hands-on-part-1_EN-inactif.ipynb     <- no file yet
    1430_hands-on-part-1_EN.ipynb             <- supplied, appears on the site

Copy the placeholder's name, remove "-inactif", and put your file in
docs/downloads/Day1/. Then:

    cd c:\Users\ASUS\stg17-workshop
    python tools/build_site.py

Reload the day page with Ctrl+F5.


3. THREE FORMATS, TWO LANGUAGES
-------------------------------

    .pdf     a presentation to read or print
    .pptx    a presentation to edit
    .ipynb   a notebook

    _EN      English        _FR      French

Any subset is fine. A session may carry an English PDF and nothing else, or a
French notebook and two English PowerPoints. Only what exists is shown.


4. SEVERAL FILES FOR ONE SESSION
--------------------------------

Add a number. One button per file, in numeric order:

    1430_hands-on-part-1_EN-1.ipynb     ->  "IPYNB · EN (1)"
    1430_hands-on-part-1_EN-2.ipynb     ->  "IPYNB · EN (2)"

When a second file arrives, number the first one too. An unnumbered file left
beside a numbered one is neither an error nor what anyone meant, so

    python tools/downloads.py

reports it under "Numbering to sort out".

A label may follow the number, and the button shows it instead of the figure:

    1430_hands-on-part-1_EN-2-exercises.ipynb   ->  "IPYNB · EN · exercises"


5. WHAT A NOTEBOOK GETS
-----------------------

A supplied .ipynb produces two things on the day page:

  - a download button, which works immediately and offline
  - a Colab badge, which opens the notebook in one click

The Colab badge builds a URL into this repository on GitHub. It only resolves
once the repository is pushed under the real organisation — `github.org` in
config/workshop.yml is still a placeholder. Until then the download button is the
path that works, which is why both are offered.


6. THE NAMING RULE, IF YOU EVER NEED IT
---------------------------------------

    <start time>_<short title>_<EN|FR>[-<n>][-<label>].<pdf|pptx|ipynb>

Never write ".en." or ".fr.". The site's bilingual plugin claims any such segment
in any filename and would publish only one of the two languages, silently. That
already cost half the slide decks once.

You should not need to type any of this: the placeholder already has the name.


7. USEFUL COMMANDS
------------------

    python tools/downloads.py             what is supplied, what is missing
    python tools/downloads.py --missing   only what is still needed
    python tools/downloads.py --day 2     one day at a time
    python tools/downloads.py --init      recreate placeholders after an agenda change
    python tools/build_site.py            publish what you have dropped

`--init` never overwrites a file you supplied.


8. BEFORE PUBLISHING TO GITHUB
------------------------------

These files are committed and served publicly from GitHub Pages.

  - Check a notebook carries no API key, token or password. `python
    tools/check_notebooks.py` scans docs/downloads/ for exactly that, and also
    refuses notebooks that still carry execution outputs.
  - Check a presentation contains nothing unpublishable: unreleased figures,
    microdata, internal drafts, personal data.
  - Keep files under about 10 MB. Every megabyte is cloned by everyone who clones
    the repository.
