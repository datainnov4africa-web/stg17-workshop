Five days, 27 contact hours, thirteen hands-on laboratories. Every presentation
and notebook is supplied in **English and French**. The country registry covers
**every African Union member state**: from an ISO3 code, `stg17.countries`
resolves the bounding box, the UTM zone, the satellite tiles and the WorldPop
codes — computed rather than tabulated.

## Quick start

**Participants** — read the
[prerequisites](https://datainnov4africa-web.github.io/stg17-workshop/before/prerequisites/),
then run the
[environment check](https://datainnov4africa-web.github.io/stg17-workshop/before/environment-check/).
The notebook is distributed with the workshop materials: your facilitator sends
you the link.

**Facilitators and contributors:**

```bash
git clone https://github.com/datainnov4africa-web/stg17-workshop.git
cd stg17-workshop
pip install -r requirements-dev.txt
python tools/serve.py          # regenerate everything, then preview
#
# The site is served under the GitHub Pages path, NOT at the root:
#   English   http://127.0.0.1:8000/stg17-workshop/
#   Français  http://127.0.0.1:8000/stg17-workshop/fr/
```

## What is in here

| Path | What it is |
|---|---|
| `config/workshop.yml` | Every placeholder value: GitHub org, endpoints, default countries |
| `config/agenda.yml` | **The agenda, as data.** The website's day pages are rendered from it |
| `stg17/` | The shared Python package — country registry, AfDB theme, bilingual runtime, NTL and boundary engines |
| `docs/downloads/DayN/` | **Where you drop a supplied deck or notebook.** See `maintainer/HOW-TO-ADD-FILES.txt` |
| `docs/` | The MkDocs site. `page.md` is English, `page.fr.md` is French |
| `country-template/` | The repository each country copies to publish its results |
| `tools/` | The build scripts. Everything derived is regenerated by `build_all.py` |
| `maintainer/` | Not published: placeholders, facilitator kit, dry-run checklist |

## The design decisions worth knowing

**One country variable.** `stg17.countries` holds the AU member states with
their bounding boxes; VIIRS tile selection, UTM zone, map extent and WorldPop
codes are *computed*, not tabulated. A boundary file is resolved from the local
mirror, then geoBoundaries, then a file the participant brings — normalised into
the same column names whichever it was, so the analysis code has no conditionals.

**Nothing is written twice.** The agenda is one YAML file, and the build emits
every day page, the laboratory register and the week view from it, in both
languages. CI fails if a generated page drifts from its source — which is what
stops the French material quietly falling a month behind the English.
Presentations and notebooks are not generated at all: they are supplied, and the
build renders buttons only for the files that are actually there.

**Every laboratory has a fallback that actually runs.** Pre-clipped country
extracts prepared in advance, an Earth Engine variant that downloads nothing, DuckDB
when the Elasticsearch cluster is unreachable, and one reference country prepared
end to end. Bandwidth is the most common cause of laboratory failure, and the
material is built around that fact rather than hoping against it.

**The limitations statement is a deliverable.** A proxy indicator published
without an honest account of what it cannot support is not a statistical product.
Day 4 turns that statement into a formal document validated against the
participant's own official subnational figures.

## Editing

| To change | Edit | Then run |
|---|---|---|
| A session, its time or its Action Plan mapping | `config/agenda.yml` | `python tools/build_site.py` |
| A presentation or a notebook | drop the file in `docs/downloads/DayN/` | `python tools/build_site.py` |
| The AfDB palette | `stg17/theme.py` | `python -m stg17.theme --emit-css` |
| Shared vocabulary | `stg17/i18n.py` | `python tools/build_site.py` |
| The GitHub org, endpoints, dates | `config/workshop.yml` | `python tools/build_all.py` |

Never edit a file under `docs/dayN/` — it is generated from `config/agenda.yml`,
and CI will tell you so.

Presentations and notebooks are not generated here at all: every one of them is
supplied. Drop the file in `docs/downloads/DayN/` under the name the placeholder
in `maintainer/placeholders/DayN/` gives it, and run `python
tools/build_site.py`. The full rule is in `maintainer/HOW-TO-ADD-FILES.txt`.
