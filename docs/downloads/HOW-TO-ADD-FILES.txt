STG17 — HOW TO ADD A PRESENTATION TO THE WORKSHOP SITE
=======================================================

Short version: find the placeholder, rename your file to match it minus
"-inactif", drop it in the same folder, rebuild. Nothing else to edit.


1. THE FOLDERS
--------------

One per day of the workshop:

    docs/downloads/Day1/
    docs/downloads/Day2/
    docs/downloads/Day3/
    docs/downloads/Day4/
    docs/downloads/Day5/

Inside each, one empty placeholder per session, per language, per format. They
are sorted by start time, so the folder reads in the order of the day.


2. ACTIVATING A FILE
--------------------

A placeholder carries "-inactif" before the extension. It means: nothing supplied
yet, and the site shows no button for it.

    1400_ai-infrastructure_EN-inactif.pdf     <- no file yet, link is dead
    1400_ai-infrastructure_EN.pdf             <- supplied, link is live

So: take the presentation you prepared, name it exactly like the placeholder but
WITHOUT "-inactif", and put it in the same Day folder.

You can delete the placeholder afterwards or leave it — it is ignored either way.

PowerPoint works identically: rename the .pptx placeholder instead.

    1400_ai-infrastructure_FR.pptx

Any subset is fine — PDF only, PPTX only, one language or both. Only what exists
is shown.


3. THE NAMING RULE, IF YOU EVER NEED IT
---------------------------------------

    <start time>_<short title>_<EN|FR>.<pdf|pptx>

    1400        session start, so files sort into running order
    ai-infra…   the title, cut at the first colon or dash
    _EN         language, after an UNDERSCORE

Never write ".en." or ".fr.". The site's bilingual plugin claims any such segment
in any filename and would publish only one of the two languages, silently. That
already cost half the slide decks once.

You should not need to type any of this: the placeholder already has the name.


4. REBUILD
----------

    cd c:\Users\ASUS\stg17-workshop
    python tools/build_site.py

Then reload the day page with Ctrl+F5. The button appears under the session
description.

To see what is supplied and what is still missing:

    python tools/downloads.py
    python tools/downloads.py --missing
    python tools/downloads.py --day 2

To recreate placeholders after the agenda changes:

    python tools/downloads.py --init

That never overwrites a file you supplied.


5. BEFORE PUBLISHING TO GITHUB
------------------------------

These files are committed to the repository and served publicly from GitHub
Pages. Check that a presentation contains nothing that cannot be public:
unreleased figures, microdata, internal drafts, personal data.

Size matters here — every megabyte is cloned by everyone who clones the
repository. Keep a deck under about 10 MB; compress images before exporting.


6. AND THE NOTEBOOKS?
---------------------

Notebooks work the other way round. You do NOT drop an .ipynb anywhere:
`tools/build_notebooks.py` would overwrite it on the next run. Each laboratory
has ONE source in notebooks/_masters/, and the build produces the four variants:

    notebooks/day1/D1_RAG_Assistant_EN.ipynb
    notebooks/day1/D1_RAG_Assistant_FR.ipynb
    notebooks/day1/D1_RAG_Assistant_EN_open.ipynb
    notebooks/day1/D1_RAG_Assistant_FR_open.ipynb

That is deliberate: English and French, guided and open, cannot drift apart if
they come from the same file.

To attach a notebook to a session:

  a. write notebooks/_masters/<name>.master.py
  b. run    python tools/build_notebooks.py
  c. in config/agenda.yml, under `labs:`, set
         notebook: <the stem, without _EN / _FR>
         status: ready
  d. link the session to it with    lab: <the fiche key>

Until `status: ready`, no Colab badge is shown — deliberately. A badge that
returns a 404 on Thursday morning is worse than no badge at all.
